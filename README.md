# netspeed

Консольный скрипт для измерения скорости скачивания. Делает N последовательных GET-запросов
к одному URL (по умолчанию 10), дожидается полного ответа на каждый и печатает время запросов,
объём скачанных данных и скорость скачивания.

## Требования

- Python 3.10 или новее
- [httpx](https://www.python-httpx.org/) — единственная зависимость, ставится из `requirements.txt`
- Доступ к тестируемому адресу

## Установка и запуск

macOS / Linux:

```bash
git clone https://github.com/Bekzat64/netspeed.git
cd netspeed
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python netspeed.py "https://speed.cloudflare.com/__down?bytes=10000000"
```

Windows (PowerShell):

```powershell
git clone https://github.com/Bekzat64/netspeed.git
cd netspeed
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python netspeed.py "https://speed.cloudflare.com/__down?bytes=10000000"
```

Если PowerShell запрещает запуск `Activate.ps1`, можно не активировать окружение и вызывать
интерпретатор напрямую: `.venv\Scripts\python netspeed.py "<URL>"`.

URL лучше брать в кавычки: в zsh символ `?` иначе воспринимается как шаблон имени файла.

### Параметры

```
python netspeed.py URL [-n N] [--timeout SECONDS]
```

| Параметр | По умолчанию | Описание |
|---|---|---|
| `URL` | — | Адрес для скачивания, только `http://` или `https://` с указанием хоста |
| `-n`, `--requests` | 10 | Число последовательных запросов, не меньше 1 |
| `--timeout` | 30 | Таймаут в секундах на каждую сетевую операцию (подключение, чтение, запись), больше 0. Это не ограничение на общее время запроса: медленная, но непрерывная загрузка не прервётся |

### Тестовые адреса

- `https://speed.cloudflare.com/__down?bytes=10000000` — 10 MB, основной вариант.
- `https://fsn1-speed.hetzner.com/100MB.bin` — альтернатива, 100 MiB, сервер в Германии.
  На медленном или далёком канале один запрос может занять минуты, поэтому начните с `-n 1`.

Если Cloudflare отвечает `ERROR   HTTP 403`: он отказывает в больших размерах
(например, `bytes=100000000`). Это ограничение размера, а не блокировка IP — используйте
10 MB или файл Hetzner.

### Коды завершения

| Код | Значение |
|---|---|
| 0 | Хотя бы один запрос успешен |
| 1 | Все запросы завершились ошибкой |
| 2 | Неверные аргументы командной строки |
| 130 | Прервано по Ctrl+C (итог печатается по завершённым запросам) |

## Единицы измерения

Все префиксы десятичные (SI), как у интернет-провайдеров и speedtest.net.

| Величина | Единица | Определение |
|---|---|---|
| Скорость (основная) | Mbit/s | 1 Mbit = 1 000 000 бит |
| Скорость (в скобках) | MB/s | 1 MB = 1 000 000 байт; 1 MB/s = 8 Mbit/s |
| Объём | MB и точное число байт | 1 MB = 1 000 000 байт |
| Время | секунды, 3 знака после запятой | |

Не путайте с двоичными единицами: 1 MiB = 1024 × 1024 = 1 048 576 байт. Например, файл
Hetzner `100MB.bin` на самом деле имеет размер 100 MiB, поэтому скрипт показывает 104.86 MB:

```
Downloaded:        104.86 MB (104,857,600 bytes)
```

## Методика

**Время запроса.** Отсчёт (`time.perf_counter()`) начинается непосредственно перед отправкой
запроса и заканчивается после чтения последнего байта тела ответа. В него входят DNS-запрос и
установка соединения (если они нужны), ожидание ответа, все редиректы и скачивание тела.

**TTFB** (time to first byte) — время от отправки запроса до получения заголовков финального
ответа.

**Объём** — байты тела ответа в том виде, в каком они пришли из сети, без HTTP-заголовков и
накладных расходов TCP/TLS. Тело читается частями по 64 KiB и сразу отбрасывается, целиком в
памяти не хранится. В метрики попадают только успешные запросы.

**Скорость = общий объём / суммарное время успешных запросов**, а не среднее скоростей
отдельных запросов. Среднее скоростей даёт каждому запросу одинаковый вес независимо от его
длительности, поэтому короткие быстрые запросы весят столько же, сколько длинные медленные.
Общий объём / общее время — это фактическая пропускная способность. В прогоне выше среднее
по столбцу `speed` равно 55.0 Mbit/s, а реальная скорость — 800 Mbit / 15.227 s = 52.5 Mbit/s.

**Keep-alive.** Все запросы идут через один `httpx.Client`, поэтому TCP+TLS-соединение
переиспользуется. Первый запрос медленнее по двум причинам:

1. Его TTFB включает DNS и установку TCP+TLS: в прогоне выше 0.617 с против примерно 0.115 с
   у остальных (около +0.5 с).
2. На свежем соединении скачивание тела замедляет TCP slow start: окно отправки растёт
   постепенно, это ещё около +0.6 с.

Последующие запросы используют уже «разогретое» соединение. По той же причине прогон с `-n 1`
дал 37.2 Mbit/s против 52.5 Mbit/s для десяти запросов.

**Сжатие.** Скрипт отправляет `Accept-Encoding: identity`, то есть просит сервер не сжимать
ответ, и считает байты через `response.iter_raw()` — до распаковки. Если сервер всё равно
пришлёт сжатые данные, будет посчитан реально полученный объём, а не распакованный.

**Редиректы** выполняются автоматически. Статус и объём берутся из финального ответа, время
включает все переходы.

**Ошибки.** Запрос считается неуспешным, если:

- произошла сетевая ошибка или таймаут;
- финальный статус не 2xx;
- соединение оборвалось раньше, чем пришло заявленное в `Content-Length` число байт
  (httpx сообщает об этом как `RemoteProtocolError`).

Неуспешный запрос печатается, прогон продолжается. Ctrl+C останавливает прогон и печатает
итог по уже завершённым запросам. Для ожидаемых ошибок выводится одно понятное сообщение без
трейсбека.

**Таймаут** в httpx действует на каждую сетевую операцию отдельно: `--timeout 30` означает,
что подключение не дольше 30 с и между порциями данных проходит не больше 30 с. Общая
длительность запроса не ограничена.

## Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты не обращаются в интернет: интеграционные тесты поднимают локальный `http.server` на
свободном порту в фоновом потоке. Покрыты расчёт метрик, число запросов и объём, 404,
редирект, оборванное тело, таймаут, Ctrl+C и неверные аргументы.

## Ограничения

- **Одно соединение.** Скрипт качает последовательно через одно TCP-соединение, поэтому
  результат обычно ниже, чем у speedtest.net. Speedtest открывает несколько параллельных
  соединений к ближайшему серверу и суммирует их. Скорость одного TCP-соединения ограничена
  размером окна и задержкой до сервера (примерно окно / RTT), в начале её сдерживает slow
  start, а потеря пакетов сильнее сказывается на одном соединении, чем на нескольких.
- **Измеряется скорость до конкретного сервера**, а не канала в целом: результат зависит от
  расстояния, маршрута и нагрузки на сервер. Например, в моих прогонах файл Hetzner дал
  4.4 Mbit/s, а Cloudflare — 52.5 Mbit/s.
- **Считается только тело ответа**: заголовки и накладные расходы TCP/TLS не учитываются,
  поэтому скорость на уровне канала немного выше показанной.
- **Время включает задержку (TTFB)**, поэтому на маленьких файлах результат определяется в
  основном задержкой, а не пропускной способностью. Используйте файлы от 10 MB.
- **Только HTTP/1.1**: HTTP/2 не включён.
